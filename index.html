01 / PROGRAMACIÓN

Control de versiones

Conoce cómo se registran y administran los cambios de un proyecto.

Explorar contenido

¿Qué es?

Es un sistema que registra los cambios realizados en archivos de un proyecto, permitiendo consultar versiones anteriores y trabajar en equipo.

¿Cuáles son?

  • Local: guarda las versiones en el equipo del usuario.
  • Centralizado: utiliza un servidor central para administrar versiones. Ejemplo: SVN.
  • Distribuido: cada colaborador dispone de una copia del historial. Ejemplo: Git.

Características

Historial de cambios, comparación de versiones, ramas de trabajo, recuperación de archivos y colaboración.

Ventajas y desventajas

Ventajas: facilita el trabajo en equipo, permite recuperar versiones y rastrear modificaciones.

Desventajas: requiere aprendizaje, organización y puede generar conflictos al combinar cambios.

Funcionamiento y gestión de cambios

Se crea un repositorio, se modifican archivos, se registran los cambios mediante confirmaciones (commits) y se revisa el historial. Las ramas permiten desarrollar funciones por separado.

Ejemplos

Git, GitHub, GitLab, SVN y Mercurial.

02 / INFORMACIÓN

Persistencia y acceso a datos

Descubre cómo las aplicaciones almacenan y consultan información.

Explorar contenido

Definición

La persistencia permite conservar información aunque una aplicación se cierre o un dispositivo se reinicie.

Características

Almacenamiento, recuperación, actualización, organización y protección de información.

Formas de persistencia móvil

  • Archivos: guardan documentos, imágenes y configuraciones.
  • Bases de datos locales: almacenan información en el dispositivo, por ejemplo SQLite y Room.
  • Bases de datos remotas: almacenan datos en servidores y se consultan mediante servicios web.

Tipos de datos almacenables

Texto, números, fechas, preferencias, imágenes, documentos, registros y datos estructurados.

Mecanismos de acceso

  • Bibliotecas de clases: proporcionan funciones para leer y escribir datos.
  • SQLite: motor de base de datos relacional local.
  • ORM: relaciona objetos del programa con tablas de bases de datos. Ejemplo: Room.

Autenticación y servicios web

La aplicación solicita identificación, obtiene o utiliza un token de acceso y realiza peticiones HTTP a una API. El servidor valida la solicitud y responde con información, frecuentemente en formato JSON.

Ejemplos

SQLite, Room, Firebase, archivos JSON y API REST.

03 / HARDWARE

Gestión de sensores

Aprende cómo los dispositivos móviles detectan su entorno.

Explorar contenido

Definición

Los sensores son componentes que detectan cambios físicos o ambientales y proporcionan datos al dispositivo.

Tipos de sensores

  • Acelerómetro: detecta aceleración y movimiento.
  • Giroscopio: mide la rotación.
  • Proximidad: detecta objetos cercanos.
  • Luz ambiental: mide la iluminación.
  • GPS: proporciona información de ubicación.
  • Magnetómetro: detecta el campo magnético.

Proceso de gestión

  1. Habilitación: comprobar disponibilidad y permisos necesarios.
  2. Obtención: solicitar lecturas mediante las API correspondientes.
  3. Procesamiento: interpretar y utilizar los datos recibidos.

Ejemplos

Aplicaciones de navegación, brújulas, podómetros, juegos y ajuste automático del brillo.

04 / DISEÑO DIGITAL

Uso de recursos multimedia

Conoce cómo integrar elementos visuales y audiovisuales.

Explorar contenido

Definición

Son elementos digitales que combinan información visual, sonora y animada para mejorar la experiencia del usuario.

Tipos de recursos

  • Imágenes: fotografías, iconos e ilustraciones.
  • Audio: música, sonidos y grabaciones.
  • Video: contenido audiovisual.
  • Animaciones: movimientos y transiciones.
  • Elementos dinámicos: gráficos, botones y componentes interactivos.

Estructura de proyectos

En Android se utilizan carpetas como res/drawable para imágenes, res/mipmap para iconos, res/raw para archivos multimedia y res/animator para determinadas animaciones.

Componentes de software

ImageView, MediaPlayer, ExoPlayer mediante AndroidX Media3, Lottie y herramientas de animación de Jetpack Compose.

Ejemplos

Galerías de fotografías, reproductores de video, aplicaciones musicales y animaciones de interfaces.

05 / CONECTIVIDAD

Servicios y notificaciones

Comprende los procesos que funcionan en segundo plano.

Explorar contenido

Definición

Son mecanismos que permiten realizar tareas, intercambiar información y comunicar eventos al usuario.

Tareas en segundo plano

Son operaciones que se ejecutan sin mantener abierta una pantalla de la aplicación, respetando las restricciones del sistema operativo.

Notificaciones

Son mensajes que informan al usuario sobre actualizaciones, recordatorios y eventos importantes. En Android se utilizan NotificationManager y canales de notificación.

Implementación

  • Proveedores de contenido: permiten compartir y consultar datos entre aplicaciones mediante permisos.
  • Tareas en segundo plano: WorkManager permite programar trabajos diferibles.
  • Notificaciones: se crean mediante NotificationCompat y se publican utilizando el administrador de notificaciones.

Servicios en la nube

Firebase, Google Cloud, Amazon Web Services y Microsoft Azure permiten almacenar datos, autenticar usuarios y ofrecer servicios.

Ejemplos

Recordatorios, sincronización de archivos, alertas de mensajes y actualización de datos.

06 / HERRAMIENTAS

Librerías y toolkits

Explora las herramientas que facilitan la programación móvil.

Explorar contenido

¿Qué es una librería?

Es un conjunto de funciones y clases reutilizables que ayudan a realizar tareas específicas.

¿Qué es un toolkit?

Es un conjunto de herramientas y componentes que facilitan el desarrollo de aplicaciones.

Librerías especializadas

  • Retrofit: comunicación con servicios web.
  • Room: almacenamiento de datos.
  • Glide: carga de imágenes.
  • Coil: carga de imágenes en aplicaciones Kotlin.

Toolkits de desarrollo

  • Jetpack Compose: interfaces nativas declarativas para Android.
  • Flutter: desarrollo multiplataforma con Dart.
  • React Native: aplicaciones móviles con JavaScript y React.
  • .NET MAUI: aplicaciones multiplataforma con C#.

Diferencias

Las librerías resuelven tareas específicas, mientras que los toolkits ofrecen un conjunto más amplio de herramientas y componentes para construir aplicaciones.

Ejemplos

Una aplicación Android puede combinar Jetpack Compose, Retrofit y Room.

07 / PROTECCIÓN

Depuración y seguridad

Aprende a detectar errores y proteger las aplicaciones.

Explorar contenido

¿Qué es la depuración?

Es el proceso de identificar, analizar y corregir errores en el código de una aplicación.

¿Qué es la seguridad?

Es el conjunto de medidas que protegen los datos, usuarios y recursos de una aplicación contra accesos no autorizados.

Herramientas de depuración

  • Logcat: muestra mensajes y errores.
  • Android Studio Debugger: permite analizar la ejecución del programa.
  • Breakpoints: detienen temporalmente la ejecución.
  • Profiler: analiza rendimiento y consumo de recursos.
  • Lint: detecta problemas y posibles mejoras.

Medidas de seguridad

  • Utilizar HTTPS.
  • Validar los datos de entrada.
  • Proteger credenciales y tokens.
  • Solicitar solamente los permisos necesarios.
  • Mantener actualizadas las dependencias.

Ejemplos

Detectar errores de inicio de sesión, analizar fallos y proteger la comunicación con un servidor.
